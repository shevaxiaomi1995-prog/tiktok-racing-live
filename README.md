# TikTok Racing LIVE

Стартовый проект интерактивных 3D-гонок для показа в TikTok LIVE Studio как источник браузера.

## Что уже заложено в прототип

- Длинная 3D-трасса «Старт → Финиш» на Three.js: широкая дорога, плавные повороты, асфальт, разметка, бордюры, ограждения, трибуны, холмы и деревья.
- Камера плавно следует за группой машин и отдаляется, когда ускорения увеличивают расстояние между лидерами и остальными.
- Детализированные 3D спорткары с цветами, фарами, колёсами и ником каждого зрителя над машиной.
- Зритель присоединяется сообщением в LIVE-чате `Старт`, `start` или `!join` (когда LIVE-коннектор передаёт событие `chat` в event-сервер).
- Таймер регистрации на 3 минуты запускается только после набора минимального количества участников (по умолчанию 10).
- Максимум — 50 машин. Когда лимит достигнут, новые заявки не принимаются.
- Базовое время прохождения трассы — 5 минут (300 секунд). Сверху показывается общее прошедшее время и цель 05:00. Ускорения позволяют отдельным машинам приехать раньше.
- Каждая машина получает точное время пересечения финиша. Гонка продолжается, пока не финишируют все участники; если замедления задержали гонщика, общее время может превысить 05:00.
- После финиша всех машин появляется полный список мест и времени финиша; результаты показываются 18 секунд, затем автоматически открывается новый набор.
- После показа итогового протокола все участники выходят, затем начинается новый набор.
- Таблица победителей хранит число побед и участий; она сохраняется в браузере и может быть сброшена вручную.
- В панели ведущего настраиваются лимиты, таймеры, порог лайков и правила подарков.
- Лайки суммируются отдельно для каждого зрителя: каждый набранный порог выдаёт ускорение.
- Для каждого подарка можно задать эффект, длительность и силу. Доступны ускорение, щит, замедление лидера, сдвиг назад и оглушение.
- Включены тестовые кнопки, чтобы проверить механику без TikTok.
- Есть Node.js/Express + WebSocket сервер-приёмник нормализованных событий.

## Локальный запуск

1. Установи Node.js 20 или новее.
2. Скопируй `.env.example` в `.env`.
3. В терминале в папке проекта выполни `npm install`.
4. Запусти `npm run dev`.
5. Открой `http://localhost:5173`.
6. В панели ведущего используй тестовые кнопки «Старт», «+100 лайков», отправку подарка и пакость лидеру.

Тестовые кнопки только имитируют события и не отправляют реальные сообщения или подарки в TikTok.

## Приём событий

Отправляй нормализованные JSON-события на `POST /api/events` с заголовком `Authorization: Bearer YOUR_EVENT_INGEST_TOKEN`. Формат событий и примеры находятся в [`bridge/README.md`](bridge/README.md).

Не включай `ALLOW_DEMO_EVENTS=true` на публичном сервере. В production используй HTTPS/WSS, а токен оставляй только на серверной стороне.

## Размещение

### Frontend на Vercel

Репозиторий рассчитан на Vercel как Vite-приложение: команда сборки `npm run build`, папка результата `dist`. На первом деплое сайт откроется в режиме предпросмотра; тестовые кнопки в панели ведущего работают без TikTok и без event-сервера.

Для импорта выбери репозиторий `shevaxiaomi1995-prog/tiktok-racing-live`, Framework Preset `Vite`, Build Command `npm run build`, Output Directory `dist`. Не добавляй секреты на frontend.

### LIVE event-сервер

`server/index.js` — отдельный Node.js/Express + WebSocket процесс. Для настоящих LIVE-событий его нужно разместить отдельно на хостинге, поддерживающем постоянно работающий Node.js-процесс и WebSocket, и задать на Vercel переменную `VITE_WS_URL=wss://АДРЕС_СЕРВЕРА/ws` с последующим redeploy. Не задавай её до запуска event-сервера. В Vercel Functions поддержка WebSocket появилась, но текущий `server/index.js` ещё не переписан в формат Function; нельзя считать его автоматически работающим на Vercel.

Для production event-сервера задай `EVENT_INGEST_TOKEN` и `ALLOW_DEMO_EVENTS=false`. Не включай демо endpoint на публичном сервере.

## Что ещё не подключено

Это рабочая локальная основа игры, но не готовый TikTok-коннектор. Авторизация TikTok, получение реальных чатов/лайков/подарков и автоматическое обнаружение начала эфира должны быть добавлены отдельным адаптером и проверены на реальном тестовом эфире. Событие `live_start` уже поддерживается: когда коннектор его отправит, таблица побед будет автоматически очищена. Ручной сброс уже доступен в панели.

В этой версии статистика хранится в localStorage конкретного браузера. Для общей статистики между устройствами и надёжного хранения истории понадобится база данных на следующем этапе.
